# Device room socket authorization (local opt-in)

`SOCKET_DEVICE_AUTH=true` enables device authorization; unset/other values preserve legacy room socket behavior. This also enables the existing management socket authentication, so management clients must send an access token in `handshake.auth.token`. Device clients use numeric `roomId` and `clientType` (`control` or `video`) in the query, and `handshake.auth.deviceProof`. Provision the proof via the device authorization HTTP routes before connecting. Unrelated clients without these device fields can still connect, but cannot invoke room events. Both approved device types currently have the same room-event permissions; management staff/admin can act across rooms.

Each room event checks the device's current slot and payload room binding. Slot approval/revocation via the supplied HTTP routes disconnects locally connected devices before the write and blocks racing handshakes. This is **single-process only**: other replicas, direct database writes or direct foundation calls bypass immediate disconnect. An external revoke can leave an idle socket subscribed to broadcasts until it sends another room event. Do not enable as a security boundary across processes without shared invalidation and coordination. In-flight handler work already dispatched before revocation is not cancelled. HTTP room/music endpoints and non-room socket events are outside this flag's scope. Deploying requires upgrading devices and management clients first; no deployment is performed here.
